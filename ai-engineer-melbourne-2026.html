Main Themes from the Conference

1. Production Reality, Not Prototypes

Companies shared real production experiences - what worked, what failed, and actual costs. Examples: $1.5M/year productivity gains at SEEK, systems handling 250M+ users at Canva, and 10% engagement lifts at REA Group.

2. Security Through Smart Design

You can't just "block bad things" with AI systems. Instead, design systems that stay safe even when things go wrong. Think seatbelts, not just careful driving.

3. Memory is Critical

The difference between a demo and a production AI agent is whether it can remember what it's doing across hours or days - like the difference between a sticky note and a proper filing system.

4. Testing is Everything

Having good ways to measure if your AI is working correctly is more important than tweaking prompts. It's like having a thermometer vs. just guessing if food is cooked.

5. Cost Matters

AI costs directly affect what features you can build. It's like choosing between express shipping or regular - sometimes the cheaper option is fine.

Day 1 June 3, 2026 - Software Engineering Track

10 sessions from the Software Engineering track with full transcripts:

1. Observability & LLM Evaluation at Scale ✓ Full Transcript

Speaker: Sergei (Canva)
What it's about: How Canva built production-grade AI evaluation for 260M+ users through layered evaluation, trace sampling, and democratized quality assurance.

Key Takeaways:

Five-Tier Layered Evaluation System

Build quality through multiple validation layers: (1) Offline evaluations with ground truth datasets, (2) Shadow runs against live traffic with zero user impact, (3) LLM-as-a-judge with model diversity, (4) Human QA review for domain expertise, and (5) Live metrics including AB tests and CSAT scores.

Real impact: One PM improved accuracy from 82% → 98% iteratively without engineering support.

Traces Became the Language Teams Speak

At scale with 10M+ Help Assistant interactions/month, cross-team debugging collapsed to simply sharing trace IDs. Upload traces to separate database and sample to focus on automations, escalations, and issues - avoiding paying for 90% of low-value traces.

Democratize Quality Evaluation

"Evals are everyone's job now" - PMs, QAs, and engineers all ship evals. Enable non-engineers to iterate on prompt improvements independently using offline evaluation frameworks. AI engineers are no longer the bottleneck.

Scale: 260M+ monthly active users, 20+ LLM evaluators processing 30k+ traces/day, 10k+ shadow run traces daily

2. Fail Fast, Fix Faster: Why Faster Models Can Beat Smarter Ones ✓ Full Transcript

Speaker: Andrew Fisher (VP Digital Science, Tetratherix)
What it's about: How faster iteration loops with cheaper models can outperform expensive frontier models when you have good feedback systems.

Key Takeaways:

The Fastest Loop Wins

Mercury 2 (cheaper, faster model) achieved 100% pass rate in 6s mean time by iterating through feedback loops, while GPT-5.4 took 88s trying to one-shot solutions. When agents can iterate quickly with dense feedback and cheap error detection, speed beats raw intelligence.

Dense Feedback Enables Fast Improvement

Requirements for fast loops: (1) Dense feedback with specific error messages, (2) Cheap error detection using deterministic checks before LLM, (3) Fast feedback process with no external latency. The test setup used 47 parallel tests with ~300ms execution and specific failure feedback.

Validation Is the Product

"Small gains accumulate" - combining fast feedback with fast iteration compounds advantage over time. Build agent harnesses that support rapid run → validate → inform next turn loops.

Benchmark Results: Mercury 2: 100% pass, 6s mean. GPT-5.4 Mini: 100% pass, 41s mean. GPT-5.4: 100% pass, 88s mean. Gemini 2.5 Flash: 80% pass, 77s mean.

3. Building Interactives at Scale Using AI ✓ Full Transcript

Speaker: Stile Education
What it's about: Automating deployment of 250+ interactive educational simulations using AI-driven bootstrap workflows and custom infrastructure.

Key Takeaways:

AI-Driven Bootstrap with Evaluation Loops

Core pattern: vibe-coded scripts with evaluation. Run discovery → migrate to monorepo → setup CI/deployment → test. Allow the agent to iteratively refine with `run_with_evaluation(retries=7)` until success criteria met. The code matters very little; the schema, tests, and guardrails matter.

Good Engineering Practices Amplify with AI

"Don't sell yourself short" - AI amplifies both good practices and bad. Clean signal (treating warnings as errors) teaches agents to recognize quality. Organizations with strong foundations see AI multiply effectiveness; those with technical debt see problems multiply.

Scale: 250+ interactive simulations deployed, 1,978 agents monitored, 126 unclustered pipelines managed

4. Coding Is 15% of Engineering Work ✓ Full Transcript

Speaker: Je Cornwall (SEEK)
What it's about: Why focusing only on coding speed misses the real bottlenecks, and how to identify your actual constraints.

Key Takeaways:

Coding Often Isn't Your Constraint

Work breakdown: Coding 15%, Collaboration 20%, Design 10%, L&D 20%, QA 20%, Other 15%. Activities AI cannot easily accelerate include collaboration, design (both require human judgment), L&D (learning requires time), and QA (requires domain expertise). Don't expect weekend results from coding AI when coding isn't the bottleneck.

Measure Constraints, Then Design Targeted Interventions

Real constraint analysis revealed: Build & Test Experience -24 points, Decision Making -12 points, Cross-team Collaboration -15 points (vs benchmark). Each required different interventions beyond coding acceleration.

Results: +3 DXI points, 18,000 hours/year reclaimed, ~$1.5M/year productivity value, ~20% PR throughput increase

5. From Zero to Production: Shipping LLM Products Safely ✓ Full Transcript

Speaker: Michael Zhang (Principal AI Engineer, MYOB)
What it's about: How MYOB's 15-engineer team shipped AI chat to production safely through narrow scope, progressive rollout, and security-as-architecture.

Key Takeaways:

Start Narrower Than You Think

DID NOT build: agent that does everything, general copilot, do-anything chat. DID build: small set of hero questions scoped to one domain, classified paths, only domain-relevant tools, read-only access, small set of golden answers for evaluation. "Narrow scope is what makes everything else possible. Bounded cost, latency, hallucination surface."

Security Is the Architecture, Not a Feature

Eight-layer defense: (1) Scope & topic lock, (2) Advice boundary, (3) Model choice for injection resistance, (4) Infra-level filters in BLOCK mode, (5) Input length cap, (6) Language stack deterministic checks, (7) Per-user rate limits, (8) Output sanitization. Multiple rounds of external pen testing before each rollout phase.

Approach: Progressive rollout (Week 1 small → beta → GA based on data), kill switch successfully used in production, multiple pen tests

6. Multi-Armed Bandits: The Scientific Shotgun for Evals ✓ Full Transcript

Speaker: Ron Au (Canva/Leonardo.Ai)
What it's about: Using smart testing strategies (bandit algorithms) to find the best AI settings faster and cheaper than traditional A/B testing.

Key Takeaways:

Bandit Allocation Reduces Regret vs Fixed Testing

Traditional A/B tests freeze with fixed allocation. Bandit allocation adaptively tightens toward evidence: Warm grows as confidence builds, Direct checked periodically, Playful exits early. Fixed exploration keeps paying for known losers; bandits minimize wasted effort.

Thompson Sampling Optimizes Exploration

Key insight: As more data arrives, posterior distributions narrow. Sample from uncertainty → update beliefs → reallocate → repeat. At Chat 50: four wide overlapping distributions. At Chat 1,000: very narrow with Warm clearly dominant.

Application: Both online experimentation (traffic allocation) and offline evaluation (token budget allocation across model variants)

7. Agents Don't Like Your APIs ✓ Full Transcript

Speaker: Mike Chambers (AWS)
What it's about: How to design APIs that agents can actually use effectively, with four key principles for agent-friendly design.

Key Takeaways:

Principle 1: Outcomes, Not Operations

Bad: 12 granular tools requiring 10+ API calls to answer one question. Good: 5 outcome-oriented tools where each completes a full workflow (get_latest_invoice_status, find_overdue_invoices, generate_invoice_report). One call replaces 10+, reducing tokens and errors by orders of magnitude.

Principle 2: Flatten Arguments

Bad: Nested dict with ambiguous structure. Good: Explicit typed parameters like `def search_invoices(email: str, status: Literal["all", "draft", "sent"], limit: int = 20)`. Flatten hierarchies; make parameters explicit and typed.

Principle 3: Instructions Are Context

Bad: "Not found" (404). Good: "No customer found with email 'alice@acme.com'. Use search_invoices_by_amount() to search by amount range instead." Error messages should guide agents toward alternative paths.

AWS Guidelines: Tools per server <50, Parameters per tool <8, Response size <10KB, Naming: domain_noun_verb

8. Infrastructure as Context: Building AI Control Planes ✓ Full Transcript

Speaker: Jay Wren (StackQL)
What it's about: Treating infrastructure as queryable data with SQL, adding policy gates, and using semantic tool selection for safe agent access.

Key Takeaways:

Query Live Infrastructure State, Not Static Files

Problem: Desired state (code) diverges from live state (actual cloud). Solution: Steampipe/StackQL expose live cloud APIs as SQL tables. Query: `SELECT account_id, instance_id FROM aws_ec2_instance WHERE instance_state = 'running'`. One SQL dialect for 150+ cloud plugins.

Four-Layer Safe Agent Architecture

Layer 1: State as queryable data (SQL over APIs). Layer 2: Skills as reusable runbooks (~100 tokens per skill). Layer 3: AI gateway for governance (model routing, tool filtering, observability). Layer 4: Cedar policy engine for authorization guardrails.

Semantic Tool Selection Scales Beyond Prompts

From 200+ registered tools, retrieve top 5 relevant for each request. "Tool selection becomes a retrieval problem: smaller prompts, less confusion, scales to thousands." Avoids bloating context with irrelevant tools.

Example: Poisoned log tries to rotate prod credentials → Cedar policy denies (not in any permit) → "Denied tool call, not a breach"

9. Agentic Healing in Production ✓ Full Transcript

Speaker: Jack McNicol (SuperIT)
What it's about: Autonomous issue detection and remediation workflows, with PR as the guardrail for agent-driven fixes.

Key Takeaways:

Three-Tier Event Urgency System

Events (highest urgency): Sentry errors, Logfire alerts, Linear bugs, Slack messages → Workflow: Triage → Discovery → RCA → Solution → Proof. Recurring (lowest urgency): Dependabot, security scans → Cron-scheduled to plan token costs.

PR Is the Guardrail, Not the Gate

Let agents run wild behind PR boundary. Stack reviewers (Greptile, Cursor BugBot, Claude Code Review) complement human review. Workflow: Events → Solution → Pull Request (Agent Review + Security + Tests) → Merge Queue.

Foundation Quality Multiplies with Automation

"Agents multiply what you already have - foundations or debt. Skip the foundation and you get automation confidently making things worse." Investment in code quality, test coverage, and deterministic checks pays exponential returns when agents automate at scale.

Key Philosophy: Warnings = errors. Clean signal teaches agents quality standards; noisy builds teach that warnings don't matter.

10. Scalable Support for 260M+ MAU ✓ Full Transcript

Speakers: Sergey Iakovlev & Sahil Bahl (Canva)
What it's about: How Canva scaled AI-powered customer support through layered evaluation, trace sampling, and async PII redaction.

Key Takeaways:

Five-Tier Evaluation for Every Change

(1) Offline: 150 labelled tickets, test changes, ship if ≥threshold. (2) Shadow Runs: 10k+ traces/day, zero impact. (3) LLM-as-Judge: 20+ evaluators, 30k+ traces/day. (4) Human QA: Weekly reviews. (5) Live Metrics: CSAT, AB tests. Week 5 CSAT dropped 12 points → trace deep-dive → fix shipped Week 6.

Async PII Redaction and Trace Sampling

Async PII redaction: Shouldn't affect runtime. Redaction pipeline runs async for safe trace analysis. Trace sampling: High volume → focus on automations, escalations, issues. Avoids paying for 90% of low-value traces.

Scale: 260M+ MAU, 10M+ Help Assistant interactions/month, 9 architectural components, 10+ agentic flows
