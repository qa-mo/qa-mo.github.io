## Available Session Transcripts

### 1. Three Lanes Below One Millisecond
**Speaker:** Vamsi Ramakrishnan (Google Cloud) & Pham Chi
**Time:** 11:00-11:20 AM
**Track:** Keynote

#### Key Highlights:

**Pham Chi on Long-Horizon Coding Agents:**

Pham discussed building AI agents that run for extended periods (48+ hours) with focus on:

- **Memory Challenges:** "Memory drift detection" in extended agent operations and skill transfer between agents
- **Architectural Shift:** Moving beyond LLMs as primary tools - "We abandon the idea of large language models. We only use large language model as a dependency, not as a first class citizen."
- **Hierarchical Reasoning Model:** Architecture from AI Lab in Singapore enabling training of smaller, dense models (20M-2B parameters) instead of massive ones
- **Performance:** Training cycles reduced from weekly checkpoints to 3-5 hours
- **Case Study:** Linux kernel migration to Rust project ran for 10+ months, improving from 12% completion to higher rates

**Key Philosophy:** "We believe that you should own your AI. We believe that the whole stack should be in your hands."

**Remaining Challenges:**
- Memory correctness verification
- Memory integration as first-class training signal

**Vamsi Ramakrishnan on Voice Agents:**

- Built gemini-rs: Open-source Rust SDK for Gemini Live
- Production systems handling "a million calls a day"
- "Latency budget is the architecture here for voice agents"
- Three-lane architecture for audio, control, and telemetry processing
- Chose Rust for performance and reliability in production environments

### 2. Kill the God Agent
**Speaker:** Adesh Gairola (raxIT Labs)
**Time:** 2:10-2:28 PM
**Track:** AI Engineering

#### Summary:

Adesh addressed securing AI agents against prompt injection attacks, emphasizing a fundamental shift in security approach.

**Core Thesis:** Organizations "can't filter our way out of problem injection" using traditional firewall approaches. Instead, systems must be designed to "operate even when prompt injection happens."

**Three-Part Security Framework (The "Three S's"):**

1. **Scope** - "Camel Architecture"
   - Uses two LLMs: a privileged LLM for planning/execution and a quarantined LLM for processing untrusted data
   - Implements "least agency" rather than just least privilege
   - Taint-tracking for PII to prevent compounding actions

2. **Sign** - Identity Management
   - Implementing "on behalf of" OAuth 2.1 standards
   - Maintains audit trails for all agent actions
   - Runtime attestation of agent capabilities

3. **Stop** - Policy Gates
   - Using policy engines like Cedar (from AWS) to control agent actions
   - Dynamic policy creation based on detected threats
   - Gates prevent unauthorized operations before they occur

**Practical Implementation:**
Adesh's company provides customers with:
- Deterministic rule-based scanning tools
- Remediation specifications
- Bespoke policies customized to their threat landscape
- Rather than fixing problems directly, empowering organizations to manage their own security

**Key Takeaway:** Shift from hoping agents won't be compromised to proving they can't cause harm even when compromised.

### 3. Multi-Armed Bandits
**Speaker:** Ron Au (Canva/Leonardo.Ai)
**Time:** 2:10-2:28 PM
**Track:** Software Engineering

#### Summary:

Ron presented on using multi-armed bandit algorithms to optimize AI systems, moving beyond rigid A/B testing to dynamic exploration strategies.

**Core Concept:** Multi-armed bandits balance exploration (trying new options) vs. exploitation (using known best options) in real-time.

**Practical Applications:**

1. **Agent Tone Optimization**
   - Testing different tones: formal, warm, direct, playful
   - Result: "Warm at 70%" performed best while "playful" performed worst
   - System dynamically allocated more traffic to better-performing variants

2. **Evaluation (Evals) Optimization**
   - Running evals with confidence bounds rather than fixed sample sizes
   - Reducing unnecessary LLM-as-judge calls to save costs
   - Applying Bayesian theory to evaluation processes

**Algorithms Discussed:**

- **Epsilon Greedy:** Foundational approach - exploit best option most of the time, explore randomly ε% of the time
- **Thompson Sampling:** More sophisticated Bayesian approach that naturally balances exploration and exploitation

**Business Value:**
- Faster convergence to optimal configurations
- Lower costs through reduced unnecessary testing
- Continuous improvement as system learns from real usage

**Key Insight:** Traditional A/B testing locks you into fixed sample sizes; bandits adapt in real-time to surface the best options faster and cheaper.

### 4. Panel: Governance & Ethics
**Moderator:** Andrew Murphy (Debugging Leadership)
**Panelists:** Aubrey Blanche, Hamish Songsmith, Nick Lothian
**Time:** 2:00-2:25 PM
**Track:** Leadership

#### Key Discussion Points:

**1. Organizational Governance & HR**

- Government contracts require consultation when roles change >10%, but tech sector knowledge work typically falls outside these requirements
- Most startups lack documented performance criteria
- **Consensus:** Eliminating HR departments won't solve underlying problems - proper governance requires socio-technical integration

**2. Privacy & Technical Solutions**

- Discussion of federated learning efforts (Google, MIT) primarily applied to ad tech
- OpenAI released PII redaction tools
- Debate around model access restrictions: Chinese labs release open-weight models while American firms (Google Gemma, Anthropic) maintain restricted access for frontier capabilities
- Question raised: Are access limitations ethically or economically motivated?

**3. Common AI Rollout Mistakes**

Three critical errors identified:

1. **Naive Risk Assessment:** "They assume that because they've done the ISO framework for that implementation, that extends to all the other uses" - treating all AI use cases as covered by one compliance framework

2. **Wrong Success Metrics:** Framing AI adoption around productivity metrics alone creates risk of employee concerns and poorly-considered solutions rather than genuine customer value

3. **Vibe-Based Rollouts:** Copying trending implementations without strategic planning

**4. Recommended Approach**

- Frame AI adoption around **mission impact or customer value creation** rather than efficiency gains
- Encourage **informed experimentation** while maintaining meaningful oversight
- Build proper governance that scales across different use cases
- Consider both the technical and human elements of AI implementation

**Key Quote:** "The most common mistake that a company will make when rolling out AI into their org" relates to inadequate governance frameworks and copying what seems to be working elsewhere without strategic thinking.

## Key Themes from Day 1

### 1. Production Reality
- Multiple talks focused on real production failures and challenges
- Emphasis on evaluation, observability, and testing over "vibe coding"
- Case studies from REA Group, MYOB, Canva, SEEK showing real implementations

### 2. Agent Architecture
- Memory and state management as critical challenges
- Security through architecture (not filtering)
- Multi-agent coordination trade-offs

### 3. Australian Perspective
- Focus on regulatory compliance (ASIC/APRA)
- "Fair go" principles in AI governance
- Local market insights (AI jobs, salaries, demand)

### 4. Beyond Hype
- "Not everything needs an LLM" - when to use simpler solutions
- Cost optimization and token economics
- Theory of Constraints over throwing more AI at problems

### 5. The Engineering Bar is Rising
- AI makes code easier but judgment scarcer
- From writing code to orchestrating AI systems
- Documentation dying, replaced by just-in-time LLM understanding
